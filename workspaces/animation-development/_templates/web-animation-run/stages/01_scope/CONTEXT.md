# 01_scope - define the animation outcome

One job: turn the request into an agreed, testable web-animation brief.

## Inputs
- Working (this run): `../../request.md`
- Reference (every run): `../../../../_shared/animation-principles.md`
- Reference (when needed): `../../../../_shared/project-profile.md`

Do NOT load other runs or assume an animation library or browser target that is not specified.

## Process
1. Stop if the target UI, user outcome, or platform is unclear; identify the missing decision.
2. Define when motion starts, what it communicates, and the expected end state.
3. Record relevant constraints, reduced-motion expectations, and observable acceptance criteria.

## Outputs
- `feature-brief.md` -> `output/`

## Check
The requester confirms the outcome and acceptance criteria are clear and testable. Record `pass` or `fail: <why>` under `## Stage Check`.
