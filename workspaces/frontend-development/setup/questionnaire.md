# Project Setup - configure the frontend workspace

One-time setup. Inspect the repository's manifests, scripts, existing components, and team conventions, then fill in [`../_shared/project-profile.md`](../_shared/project-profile.md). Preserve the current stack; do not add dependencies or migrate frameworks as part of this setup.

## Questions to answer

1. What framework, language, and package-manager versions does the project use?
2. Where is the application entry point, and where do source files and tests live?
3. What exact commands start, build, lint, type-check, and test the application?
4. Which browsers, devices, and viewport sizes are supported?
5. Which design system, component library, styling, routing, and state/data patterns should changes follow?
6. What accessibility, performance, localization, analytics, and review/release constraints apply?

If a value cannot be verified, leave it marked `Not configured` and ask the project owner before relying on it.
